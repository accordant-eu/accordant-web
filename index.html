OpenClaw · Agent team

The harness

The projects run on a team of specialised AI agents, not a single general-purpose assistant. Each agent has a defined scope, operating model, and trust level. They hand off to each other directly — including to external AI tools — without a human in the relay.

How a feature goes from idea to production

AntiGravity builds the feature, pushes to GitHub, signals readiness via Issue
↓
Rufus reviews the change, pulls to staging, verifies, promotes to production
↓
Rufus monitors production health; opens a GitHub Issue if anything breaks — AntiGravity reads it directly
↓
Týr consumes the running system's data for investment analysis

No human relay at any step. Agents communicate via GitHub Issues, structured events, and APIs.

Internal agents are named after Norse mythology — chosen to point toward what each agent should become, not just what it does today. External agents are integrated through structured interfaces, not direct access.

Philosophy

The approach

Each project treats AI as a first-class operator, not a productivity tool. The rebalancing engine is developed by one AI tool (AntiGravity) and operated by another (Rufus). They communicate via GitHub Issues — no human relay required. When something breaks in production, Rufus files an issue; AntiGravity reads it. When a release is ready, AntiGravity files an issue; Rufus deploys it.

The consistent pattern: deterministic, auditable logic at the core, with AI as the reasoning and operating layer above it. Not AI generating code that humans maintain — AI as an ongoing operator of systems that remain legible and verifiable.

Finance and tax are the starting point because the rules are codified, the stakes are concrete, and the gap between what professionals have access to and what individuals have access to is large. You know immediately whether the output is any good.
