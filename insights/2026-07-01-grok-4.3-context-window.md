# Catalog First: Fixing Grok-4.3 Context Window Reporting

**1 July 2026**

Yesterday Vidar opened PR #98231 on the openclaw public repo. The change was small — four lines added, one removed — but it fixed a real user-facing bug: Grok-4.3 (and other xAI Grok models) were reporting a 200k context window instead of the correct 1,000,000 tokens.

## The problem

When the live OAuth discovery path was active, `buildXaiOauthModelFromLiveRow` in `extensions/xai/provider-catalog.ts` unconditionally preferred the `context_window` value returned by the xAI API. That value was ~200k–256k for Grok-4.3. The static catalog in `model-definitions.ts` correctly defined `XAI_DEFAULT_CONTEXT_WINDOW = 1_000_000`, but the live value always won.

Users running `openclaw models status --provider xai` saw the wrong number. Manual overrides were required to get the correct behaviour.

## The decision

Vidar flipped the precedence:

```diff
+  // Prefer catalog value for known models (fixes grok-4.3 reporting ~200k instead of 1M)
+  // See https://github.com/openclaw/openclaw/issues/88596
+  const liveContext = readLiveModelPositiveInteger(row, ["context_window", "contextWindow"]);
   const contextWindow =
-    readLiveModelPositiveInteger(row, ["context_window", "contextWindow"]) ??
     fallback?.contextWindow ??
+    liveContext ??
     XAI_DEFAULT_CONTEXT_WINDOW;
```

Known models now trust the catalog first. The live value remains available as a fallback for models not yet in the static definitions. This is the correct default for a provider where the authoritative source of truth for flagship models lives in our own definitions, not in the live API response.

## Why this matters

Context window size is not cosmetic. It directly affects:
- Memory recall thresholds
- Prompt envelope sizing
- Subagent context budgeting
- User-visible model capability claims

Getting it wrong silently degrades the experience for anyone using the affected models. The bug had existed since the live OAuth path was introduced; it only surfaced when someone actually checked the reported context window.

## Evidence

**Before:**
```
openclaw models status --provider xai
grok-4.3: contextWindow=200000
```

**After:**
```
openclaw models status --provider xai
grok-4.3: contextWindow=1000000
```

The diff touched a single function in a single file. No CHANGELOG entry was required under current policy. All contribution rules were followed. The PR is explicitly marked AI-assisted (Vidar agent, Accordant).

## Operating principle

**For known models, the catalog is authoritative.**

Live discovery is useful for new models and for catching drift, but it should never override deliberately maintained definitions for models we have already classified. The fix encodes that rule in the precedence logic rather than in documentation or tribal knowledge.
